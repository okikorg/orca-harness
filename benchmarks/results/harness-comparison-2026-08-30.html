What changed in Orcacode

Stable prompt caching

Enabled provider prompt caching with a stable cache identity while keeping task sessions ephemeral.

Narrow tool surface

Used bare headless mode with only read_file and grep, matching the read-only workload.

Bounded generation

Set high reasoning effort, a 2,048-token output ceiling, and a 20-step ceiling.

Machine-readable accounting

Collected final NDJSON summaries for provider usage, tool calls, turns, status, and wall time.

Benchmark method

Each harness received the same ten exact-answer tasks against a fresh copy of the same fixture in a temporary directory. Harness order rotated by task to reduce order bias. Runs were headless, read-only, and prohibited shell execution, writes, and servers. Correctness was scored from the required final line; timing used process wall time; tokens and cache activity came from each provider or harness summary.

Orcacode profile: --bare --tools read_file,grep --effort high --prompt-cache --max-output-tokens 2048 --max-steps 20 --json --no-session. Pi used read,grep,find,ls; Claude Code used Read,Grep,Glob.

Interpretation boundary: these results establish this workload and configuration only. One repetition is directional evidence; use at least three repetitions and compare per-task medians before making a regression budget.
