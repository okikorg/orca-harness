Implementation guide for agents building the platform-owned worker. This document describes the current source audit; it does not define a new SDK wire protocol.

Architecture decision record · runner ↔ worker ↔ SDK

Platform owns the wire.
SDK owns the loop.

Package orca-harness-sdk inside an agent-orc-owned worker binary. Keep transport, tenant identity, profile interpretation, state envelopes, and platform MCP in the worker. Keep model/tool execution, session context, events, cancellation primitives, and recovery in the general SDK.

GOIntegration can begin now. No major SDK redesign is required. A platform adapter is an intentional architecture layer, not a workaround.
ADR / 001

The decision

Integrate now
The current SDK is sufficiently complete to act as the execution engine in a platform-owned worker. The worker must implement the agent-orc outbound protocol and translate platform concepts into SDK objects.

Do not add platform wire code to the SDK

The SDK remains transport-agnostic and reusable in CLIs, desktop apps, servers, sandboxes, and tests.

Do add a dedicated worker package

The worker is the anti-corruption layer between platform wire DTOs and the SDK’s in-process Rust API.

Target outbound protocol v1

Use the authenticated, outbound-only sandbox contract rather than making the runner dial into a worker.

Resolve capabilities per run

Build one immutable SDK Agent for each effective profile snapshot. If capabilities change, finish the active run, build a new agent, and resume the persisted SDK transcript through that agent.

Boundary testIf a concern mentions HTTP, bearer tokens, runner session IDs, tenant policy, profile selectors, state upload, sandbox readiness, or process shutdown, it belongs in the platform worker. If it concerns model invocation, tool dispatch, context, extension hooks, usage, cancellation tokens, or compaction, it belongs in the SDK.
Current protocol limitsOutbound v1 has no explicit cancel command. A runner cancellation is observed when the events handler processes another uploaded line and rejects the stream; a silent model/tool may not notice promptly. Protocol-major negotiation is also worker-side today: the runner accepts the first authenticated poll as readiness but does not inspect X-Orca-Worker-Protocol. Implement against these facts rather than stronger intended semantics.

Intentional non-goals

  • No runner HTTP client, bearer-token parser, worker command loop, or server endpoint.
  • No platform profile schema, tenant identity, tool-selector language, or sandbox placement logic.
  • No platform event DTO, timestamp policy, run correlation, state envelope, or health endpoint.
  • No assumption that one host means one platform; the same SDK should support unrelated hosts.
OWNER / PLATFORM

The protocol the worker must honor

PROTOCOL
Major version 1; worker sends X-Orca-Worker-Protocol: 1 when polling and validates every command’s protocol.
READINESS
The runner marks the session ready when the first bearer-authenticated long poll enters rendezvous, before a command is returned. Outbound workers bind no inbound health port.
VERSION CHECK
The worker sends X-Orca-Worker-Protocol: 1, but the current v1 runner does not inspect it. The worker must validate each returned command’s protocol and skip/reject an unsupported major before executing work.
COMMANDS
run, export_state, and shutdown.
RUN INPUT
runId, runner sessionId, full profile, subtask, optional runner MCP URL, resolved external MCP servers, inline skills, and context documents.
EVENTS
Chunked application/x-ndjson; one platform event per line; X-Orca-Run-Id must match the active command.
CANCEL
Transport-level and event-driven in current v1: after runner cancellation, the next event line lets the runner reject the upload and the worker then cancels its SDK token. There is no independent cancel command, so a silent in-flight model/tool is a known promptness gap. Local deadlines and process shutdown can cancel directly.
STATE
Opaque bytes uploaded with content type and optional runtime-session identity. Local sandbox state remains the fast restore path.
AUTH
Every worker request carries the session-scoped bearer token. Treat token-bearing MCP URLs as secrets.
RETRY
Runner restart and network failure are expected. Back off with jitter and preserve session state.
Preferred targetImplement the sandbox outbound contract first. A static inbound POST /run compatibility frontend can be added later over the same resolver, session registry, event mapper, and SDK execution core.
FLOW / RUN

One command from poll to result

sequencecancellation path shown in coral

Poll and authenticate

The runner marks readiness when the first authenticated poll enters rendezvous. A 204 means poll again; a transient failure means back off. The current runner does not negotiate the protocol header.

Validate command identity and version

Worker-side, require command protocol 1, matching runner session identity, non-empty run ID, profile, and subtask before executing work.

Resolve the effective capability snapshot

Build or retrieve an immutable agent for this run’s effective profile. If tools or MCP changed since the prior run, build a replacement agent rather than mutating the current one.

Open or rebind the SDK session

Use the runner-to-SDK mapping to resume the persisted transcript through the selected agent, or create one persistent SDK session and save its ID.

Start and supervise

Retain the cancellation token. Drain events and observe event-upload responses concurrently. Cancel on an observed rejection/loss, local deadline, or shutdown; document that a silent run has no prompt remote-cancel signal in v1.

Translate and upload

Emit only platform wire DTOs. End the request body after the terminal event and SDK task completion.

Checkpoint

Atomically persist local state after every run; upload the versioned opaque bundle best-effort or when explicitly requested.

fn to_wire(event: HarnessEvent, now: Timestamp) -> Option<WorkerEvent> {
    match event {
        HarnessEvent::ToolCall { tool_call_id, tool_name, input } => Some(WorkerEvent {
            type_: "tool_call", ts: now,
            toolCallId: tool_call_id, toolName: tool_name, input,
        }),
        HarnessEvent::ToolResult { tool_call_id, output, is_error, .. } => Some(WorkerEvent {
            type_: "tool_result", ts: now,
            toolCallId: tool_call_id, output, isError: is_error,
        }),
        HarnessEvent::ToolFinished { .. } => None,
        // Map the remaining supported variants explicitly.
    }
}

MAP / CAPABILITY

MCP and skills cross the membrane

Runner MCP

sessionMcpUrl is a platform streamable-HTTP capability channel. The current SDK Mcp::connect accepts a local stdio command, so the worker must adapt the platform transport.

Option A · platform Tool objects

Implement lazy search/select/feature tools in the worker and forward calls to the runner HTTP MCP endpoint. Register them through AgentBuilder::tool_arc.

Option B · bundled MCP bridge

Run a contained stdio-to-streamable-HTTP bridge and connect the existing SDK MCP manager to it. This reuses SDK catalog behavior but adds a child-process boundary.

Either option is compatible with the SDK today. Native HTTP MCP in the general harness could reduce adapter code later, but it is not a prerequisite for platform integration.

Inline skills

The platform sends complete skill bodies and base64 resources. The SDK discovers skills from contained filesystem roots. The worker chooses one of two adapters:

Materialize safely

Write a per-session skill tree, validate every relative path, set executable bits only under policy, then build Skills::from_roots and reload.

Serve in memory

Implement platform-owned activate_skill and resource tools over the inline envelope, then register them as SDK tools.

Isolation ruleNever call harness.skills() in a sandbox worker if doing so can discover unrelated home-directory skills. Construct explicit roots or in-memory tools from the command payload.
PLAN / BUILD

Smallest delivery sequence

Protocol shell with a scripted model

Implement environment validation, poll, protocol check, event upload, export, shutdown, retries, and a container/process entry point. Use a deterministic SDK model first.

Explicit event compatibility

Add worker wire DTOs and table-driven mappings for every SDK event variant. Prove timestamps, casing, terminal behavior, and cancellation on upload loss.

Session identity and bundle

Create one persistent SDK session per runner session, version the mapping, archive transcript/recovery, and exercise restart.

Profile and provider resolver

Resolve only supported models and exact capabilities. Make unsupported runtime/model/tool combinations fail visibly and closed.

Inline contexts and skills

Inject current context documents according to platform rules and expose validated skill content without ambient host discovery.

Runner MCP, then external MCP

Connect the platform tool surface first; add resolved external HTTP MCP servers and optional-server degradation second.

Conformance and packaging

Run captured protocol fixtures against the built worker image, including restart, stale run, cancellation, malformed input, and runner outage.
