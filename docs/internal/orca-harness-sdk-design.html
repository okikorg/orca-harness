Small composition layer / all harness capabilities

One Rust crate.No terminal attached.

orca-harness-sdk is a thin, meaningful facade over the existing kernel, providers, tools, tool extensions, and lifecycle extensions. It gives Rust hosts agents, runs, persistent sessions, memory, MCP, skills, and compaction without importing or emulating Orcacode’s TUI.

orcacode=orca-harness+TUI host · orca-harness-sdk=orca-harness+crate wrappers− TUI
DECISION

Build the facade, not a framework

Add one library crate named orca-harness-sdk. It owns composition and host-neutral lifecycle objects. Existing crates remain independently usable and remain the source of truth for execution. The SDK does not copy tool logic, model protocols, persistence formats, or extension hooks.

Status of code in this document The snippets specify the proposed facade API. They are examples for the implementation contract and will not compile until the new SDK crate is implemented. Names from the existing crates are called out separately in the mapping section.
IN

Meaningful defaults

One builder connects model, tools, extensions, stores, and workspace boundaries correctly.

IN

Direct control

Every built-in capability can be enabled, configured, replaced, or omitted.

OUT

No TUI

No Ratatui, Crossterm, views, keymaps, slash commands, clipboard, or terminal approval prompts.

OUT

No platform layer

No HTTP service, distributed scheduler, tenant model, VM manager, queue, or language bindings.

BOUNDARY

The SDK is a composition root

The SDK sits beside Orcacode as a second host. Both compose the same execution crates; neither depends on the other. A custom host may use the SDK for the common path and drop to the underlying crates whenever it needs lower-level control.

OBJECTS

Four objects, clear ownership

Harness
Process-level state: workspace, state directory, session index, memory store, skill catalog, and MCP manager.
Agent
Reusable immutable definition: model, prompt, limits, tool registrations, and extension configuration. It creates run-local core agents.
Session
Conversation-level state: mutable Context plus optional JSONL recorder. It can run multiple turns, compact, fork, clear, and resume.
RunResult / RunHandle
One invocation. Carries final text, usage, events, cancellation, and the completed context state.
Why not wrap one permanent core Agent? Usage meters, event channels, cancellation, and some extension state belong to one run. The SDK’s Agent should therefore be a reusable definition that assembles a fresh orca_harness_core::Agent per run while a Session retains the context.

EXAMPLE

Quick start

Cargo.tomlminimum useful host
[dependencies]
orca-harness-sdk = "0.1"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
src/main.rscoding agent + persistent session
use orca_harness_sdk::{Harness, OpenAiModel, RunRequest, ToolPreset};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let sdk = Harness::builder()
        .workspace("./my-project")
        .state_dir("./.orca-state")
        .build()?;

    let model = OpenAiModel::new("gpt-5")
        .api_key(std::env::var("OPENAI_API_KEY")?);

    let agent = sdk.agent(model)
        .system_prompt("You are a careful Rust coding agent.")
        .tools(ToolPreset::Coding)
        .build()
        .await?;

    let mut session = agent.new_session().persistent().open()?;
    let result = session.run(RunRequest::new("Explain this workspace")).await?;

    println!("{}", result.text);
    println!("usage: {:?}", result.usage);
    println!("session: {}", session.id());
    Ok(())
}

Defaults: usage metering, typed events, truncation with recoverable originals, and manual compaction are available. Shell/write access appears only because the caller explicitly selected ToolPreset::Coding.

let request = RunRequest::new("Run the tests").on_event(|event| {
    match event {
        HarnessEvent::AssistantDelta { text } => print!("{text}"),
        HarnessEvent::ToolCall { tool_name, .. } => eprintln!("start {tool_name}"),
        HarnessEvent::ToolFinished { tool_name, is_error, .. } => {

    }

Start in the background and cancel

cancel.rsRunHandle
let mut handle = session.start(RunRequest::new("Investigate all failures"))?;
let cancel = handle.cancellation_token();

while let Some(event) = handle.events().recv().await {
    if should_stop(&event) {
        cancel.cancel(); // reaches model, tools, processes, MCP, subagents
    }
}

let result = handle.finish().await?;

A started run temporarily owns the session borrow/state. The SDK should make it impossible to begin another turn before finish returns the session to an idle state.

EXAMPLE

Complete host assembly

This example uses every requested domain while staying independent of Orcacode.

full.rsall core crates, no TUI
use orca_harness_sdk::{
    Compaction, Harness, HarnessEvent, LongSessionConfig, MemoryConfig,
    OpenAiModel, RetryConfig, RunRequest, SkillDestination, ToolPolicy,
    ToolPreset, TruncationConfig,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let sdk = Harness::builder()
        .workspace("./repo")
        .state_dir("./.orca-state")
        .build()?;

    // Shared host services.
    let memory = sdk.memory().open()?;
    let skills = sdk.skills();
    skills.reload()?;

    let mcp = sdk.mcp();
    mcp.connect("project", "project-mcp --stdio").await?;

    let model = OpenAiModel::new("gpt-5")
        .api_key(std::env::var("OPENAI_API_KEY")?)
        .parallel_tool_calls(true);

    let agent = sdk.agent(model)
        .name("rust-maintainer")
        .system_prompt("Maintain this Rust workspace. Verify every change.")
        .tools(ToolPreset::Coding)
        .python()
        .todos()
        .subagents_default()
        .mcp(mcp)
        .skills(skills)
        .memory(MemoryConfig::read_write(memory))
        .extension(ToolPolicy::new().deny(["delete_file"]))
        .truncation(TruncationConfig::default())
        .tool_retry(RetryConfig::attempts(3))
        .compaction(Compaction::Automatic(LongSessionConfig {
            compact_at_percent: 80,
            tail_percent: 20,
        }))
        .build()
        .await?;

    let mut session = agent.new_session().persistent().open()?;
    let request = RunRequest::new("Review the workspace and fix the failing tests")
        .on_event(|event| match event {
            HarnessEvent::ToolCall { tool_name, .. } => eprintln!("→ {tool_name}"),
            HarnessEvent::AssistantDelta { text } => print!("{text}"),
            _ => {}
        });

    let result = session.run(request).await?;
    println!("\n\n{}", result.text);
    println!("usage: {:?}", result.usage);

    sdk.shutdown().await?;
    Ok(())
}

RULES

Lifecycle, errors, and safety

One SDK error boundary

error.rspreserve typed sources
#[derive(Debug, thiserror::Error)]
pub enum SdkError {
    Config(String),
    Workspace(#[source] std::io::Error),
    Harness(#[from] HarnessError),
    Session(#[from] SessionError),
    Memory(#[from] MemoryError),
    Mcp(#[from] McpError),
    Skill(String),
    BusySession,
    Shutdown,
}
  • Do not flatten underlying errors to strings unless no typed error exists.
  • Never include credentials in Debug, errors, events, or configuration summaries.
  • Dropping a run cancels it; dropping the final MCP/process tool owner terminates children.
  • Harness::shutdown() is explicit and idempotent; Drop remains a best-effort fallback.
  • All filesystem paths are rooted through the existing Workspace type.
  • Extension and tool ordering is deterministic and documented.
  • Custom tools and extensions are never silently granted special permissions.

Assembly order

  1. Create provider model.
  2. Apply model decorators: retry, skill mention behavior if retained, MCP schema visibility, memory recall.
  3. Create run-local event, usage, cancellation, and truncation state.
  4. Register presets, custom tools, recovery tool, memory tools, skills tool, and MCP tools.
  5. Register policy and lifecycle extensions in deterministic order.
  6. Run against the Session’s Context; sync the recorder after completion or repair.
