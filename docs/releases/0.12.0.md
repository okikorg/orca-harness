Orcacode 0.12.0 lets one agent work across several projects: `--add-dir` opens more directories to the file tools without moving the workspace root.

## Highlights

- `--add-dir DIR` (repeatable, interactive and headless) lets `read_file`, `write_file`, `edit_file`, `glob`, `grep` and the file administration tools reach `DIR` by absolute path. Relative paths, the shell's starting directory, AGENTS.md, skills, memory and saved approvals stay on `--workspace`. Added directories are listed in the system prompt and the `@` picker, inherited by subagents and sidekicks, and treated as in scope by auto mode. They are not saved with a session: pass them again with `--resume`. A missing or non-directory value fails at startup.
- File tools now accept absolute paths that point inside the workspace or an added directory; absolute paths anywhere else are still refused.

## Behavior change: symlinks that leave the workspace

Paths are now checked after symlinks are followed. A path that reaches outside the workspace and every added directory through a symlink is refused, and `grep` no longer descends through such links. Before, the file tools followed them.

If your monorepo symlinks a shared folder in from outside the repository, add the folder: the refusal names where the link points and the flag to use, for example `--add-dir /path/to/shared`. Links that stay inside the workspace or an added directory work as before.

## Install

macOS / Linux:

```sh
curl -fsSL https://orcapods.ai/orcacode.sh | sh
```

Windows (PowerShell):

```powershell
irm https://orcapods.ai/orcacode.ps1 | iex
```
