Orcacode 0.9.0 adds a Docker sandbox boundary, programmatic tool calling from `bun_repl`, images by URL, and OpenRouter cost reporting, and removes the todo tool.

## Highlights

- Sandbox boundary with a keyless Docker adapter: file tools, REPL interpreters and background processes run inside the sandbox, and host-owned containers can be named, reattached, finalized and attached to an isolated network.
- Programmatic tool calling: `bun_repl` code can call the run's registered tools, including from sandboxed subagent children.
- Images can be sent to providers by URL, and user message images persist in the transcript.
- OpenAI-compatible providers carry OpenRouter's `usage.cost` and the response id; usage reported by a failed model call is counted.
- Opt-in OpenAI service tier, verbosity and response format.
- OpenAI Agents `.codex-plugin` archives are parsed.
- SDK: run a session over a batch of input messages, attach extensions to a single run, and bind a session to a host-provisioned sandbox environment.

## Tool changes

- The todo tool and its TUI progress list are removed. Update custom tool allowlists that reference it.

## Fixes

- Sandbox hardening: protected capability directories refuse symlinked ancestors and parent traversal, managed identities are validated before any Docker command, and killed commands stop cleanly.
- Image URLs accept only http(s) and refuse credentials or malformed hosts; images carrying their own bytes are sent inline.
- Tool calls cut off mid-flight report a finish, and sandbox stdin close failures are reported instead of dropped.
- OpenAI: accept null `completion_tokens_details`, strip top-level schema combinators from tool parameters, and report a bad `text.format` as non-retryable.
- Codex plugin skill names are validated and server paths join cleanly.

## Install

macOS / Linux:

```sh
curl -fsSL https://orcapods.ai/orcacode.sh | sh
```

Windows (PowerShell):

```powershell
irm https://orcapods.ai/orcacode.ps1 | iex
```
